CREATE TABLE `vehicles` (

### 2.3 急救事件表 `emergency_events`

| 前端展示 | 数据库字段 | 类型 | 必填 | 示例 | 说明 |
|---------|-----------|------|------|------|------|
| 事件编号 | event_id | String | 是 | `EVT-20261012-01` | 事件唯一编号 |
| 120 任务号 | task120_id | String | 是 | `120-WY-88421` | 120 工单号 |
| 等级 | level | Integer | 是 | `0` | 0重症/1急症/2一般 |
| 主诉 | chief_complaint | String | 是 | `胸痛、意识模糊` | 主诉 |
| 接车地址 | pickup_address | String | 是 | `威远县连界镇` | 接车地址 |
| 目标医院 | destination | String | 是 | `威远县人民医院` | 目的地 |
| 车辆 | vehicle_id / vehicle_plate | String | 是 | `AMB-1` / `演示001` | 关联车辆 |
| 状态 | status | Integer | 是 | `1` | 见图 3 状态枚举 |
| 出警时间 | started_at | DateTime | 是 | `2026-10-12T14:05:00+08:00` | 开始时间 |
| 预计到院 | eta_hospital_minutes | Integer | 是 | `8` | 分钟 |
| 预计到患者 | eta_patient_minutes | Integer | 否 | `4` | 分钟，可空 |
| 评分方案 | score_plan | String | 否 | `胸痛绿色通道 · NEWS 关注` | 院前评分 |
| 救治方案 | treat_plan | String | 否 | `吸氧、心电监护…` | 处置方案 |

```sql
CREATE TABLE `emergency_events` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `event_id` VARCHAR(32) NOT NULL COMMENT '事件编号，如 EVT-20261012-01',
  `task120_id` VARCHAR(32) NOT NULL COMMENT '120 任务号，如 120-WY-88421',
  `level` TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '等级：0重症1急症2一般',
  `chief_complaint` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '主诉',
  `pickup_address` VARCHAR(128) NOT NULL DEFAULT '' COMMENT '接车地址',
  `destination` VARCHAR(64) NOT NULL DEFAULT '' COMMENT '目标医院',
  `vehicle_id` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '车辆编号',
  `vehicle_plate` VARCHAR(16) NOT NULL DEFAULT '' COMMENT '车牌',
  `status` TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '状态：见状态枚举',
  `started_at` DATETIME NOT NULL COMMENT '出警时间',
  `eta_hospital_minutes` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '预计到院分钟',
  `eta_patient_minutes` INT UNSIGNED NULL DEFAULT NULL COMMENT '预计到患者分钟',
  `score_plan` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '院前评分方案',
  `treat_plan` TEXT NULL COMMENT '救治方案',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_event_id` (`event_id`),
  UNIQUE KEY `uk_task120_id` (`task120_id`),
  KEY `idx_status_started` (`status`, `started_at`),
  KEY `idx_vehicle` (`vehicle_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='急救事件表';
```

索引说明：
- `uk_event_id` / `uk_task120_id`：事件与 120 工单一一对应，且支持「按 task120Id 回填登记」。
- `idx_status_started`：实时出警看板按状态 + 时间排序。
- `idx_vehicle`：事件 ↔ 车辆关联查询。

## 6. 状态与枚举值

### 6.1 会诊状态 `status`

复用 README §3.5 会诊会话状态枚举：

| code（存储） | 常量 | label（显示） | 说明 |
|-------------|------|--------------|------|
| 0 | `WAITING` | 待接诊 | 已发起，待接诊科室领取 |
| 1 | `IN_CALL` | 会诊中 | 已接诊，进入会诊室 |
| 2 | `FINISHED` | 已结束 | 会诊意见已提交 |

状态流转：`WAITING → IN_CALL → FINISHED`（发起会诊 → 接诊 → 提交会诊意见）。

### 6.2 会诊意见执行反馈 `feedback.value`

| 存储值 | 显示文本 |
|--------|---------|
| `已收到` | 已收到 |
| `已执行` | 已执行 |
| `情况有变化` | 情况有变化 |
| `请求再次联系` | 请求再次联系 |

### 6.3 临床资料类型 `kind` 与来源 `source`

- 类型 `kind`：`护理记录` / `检验记录` / `用药记录` / `评估记录` / `病程记录`。
- 来源 `source`：`local`（本机演示记录）/ `his` / `emr` / `lis`（外部系统，未接入则标记为 local）。

### 6.4 音视频模式 `media_mode`

| 存储值 | 显示文本 | 说明 |
|--------|---------|------|
| `PLACEHOLDER` | 演示占位 | 演示环境，音视频为占位，非商用 RTC |
| `RTC` | 正式 | 生产接第三方 RTC / 跨网络多方会诊 |

| 项目 | 内容 |

## 9. 交互与业务规则

## 5. 交互与边界说明

- **二次确认**：患者登记正式提交后建议前端确认（演示未做）；删除登记为软删除（`deleted_at`）。
- **字段联动**：从出警/车辆页进入登记时，`eventId`/`task120Id`/`vehicleId`/`vehiclePlate`/`chiefComplaint` 由上个页面带入（URL query / hash 传递），后端需校验这些关联字段合法（事件/车辆存在）。
- **表单校验**：`name` 必填（前端已 `required`，提交前 trim 校验）；`age` 为数字、0-150；`phone` 为可空手机号。
- **草稿 vs 提交**：同一任务号（`task120Id`）再次登记时，前端会回填上次草稿；后端对同一 `task120Id` 的正式提交应支持更新（幂等，按 task120_id upsert）。
- **状态流转**：事件状态随出车生命周期变化（出警中 → 现场处置 → 返院途中），由调度端更新。
