## 一、审查概况与表清单确认

- 实际识别 **61 张表**：§三 动态字典 2 张（dict_type、dict_item）+ §五 详细设计 59 张（5.1–5.59）。
- ⚠️ 表数量三方不一致（详见 X1）：§四标题写"共 60 张"、§四清单实际仅枚举 56 张（遗漏 5 张中间表）、全文档实际定义 61 张。
- 检查顺序与进度标记：【n/61】中 n 为该表在文档中的定义位置序（dict 两表位于 §三，位置最靠前），检查自 n=61 逆序推进至 n=1。
- 本报告只读审查，未修改原设计文档。

## 四、系统性专项（跨多表同类问题）

### S1【严重】TINYINT 状态/类型字段默认值 0 越出枚举范围（21 字段 / 20 表）
这些字段默认值 0 在各自枚举中无定义，INSERT 未显式赋值即产生非法状态数据，下游状态机/字典映射全部落空：

| 表.字段 | 枚举起点 | 表.字段 | 枚举起点 |
|---|---|---|---|
| org.org_type | 1-5 | alert.alert_type | 1-5 |
| vehicle_device.device_type | 1-3 | monitoring_unit.unit_type | 1-2 |
| bed_device.device_type | 1-2 | qc_issue.source_type | 1-5 |
| patient.source | 1-2 | qc_issue.level | 1-3 |
| patient_registration.register_type | 1-2 | qc_issue_track.action | 1-5 |
| prehospital_record.patient_type | 1-4 | edu_content.content_type | 1（仅1） |
| vital_sign.sign_type | 1-6 | assessment_record.score_type | 1-5 |
| medical_record.record_type | 1-8 | monitoring_stream.kind | 1-3 |
| consultation_member.member_role | 1-3 | vital_alert_rule.metric | 1-5 |
| care_task.source | 1-2 | ambulance_crew.crew_role | 1-3 |
| ambulance_crew_history.crew_role | 1-3 | | |

**建议**（三选一，全库统一）：① 注释补充"0-未知/未选择"使默认值合法；② 默认值改为首个合法枚举值；③ 默认值改 NULL 并由应用必填。对照说明：默认值合法的字段（如 event_status 0-已接警、work_status 0-待命）无需处理。

### S2【严重】患者主诉同步截断
patient.complaint VARCHAR(500) ← patient_registration.scene_desc VARCHAR(1000)，同步链路静默截断丢失数据。建议 complaint 扩至 VARCHAR(1000)，或同步时显式截断并告警，或 scene_desc 限 500。
