# 数据库表设计说明书

> 依据《数据库表规范.md》编制。状态枚举存数字，含义见字段注释及 `dict_item` 动态字典；多对多一律使用独立中间表；不建物理外键，仅建索引。DATE 列默认 `(CURRENT_DATE)` 依赖 MySQL 8.0.13+ 表达式默认值语法。

## 一、公共字段约定（所有表默认包含，不再逐表列出）

| 字段名 | 类型 | 默认值 | 注释 | 备注 |
|---|---|---|---|---|
| id | BIGINT UNSIGNED | 自增 | 主键 | 所有表 |
| org_id | BIGINT UNSIGNED | 0 | 数据归属机构，关联 org 表；0=平台级 | org、dict_type、dict_item 三张表除外；部分业务表为标注索引显式重复列出，含义与本行一致；业务机构字段（register_org_id、apply_org_id/receive_org_id、from_org_id/to_org_id 等）为独立语义 |
| created_by | BIGINT UNSIGNED | 0 | 创建人，关联 user 表；0=系统 | 所有表 |
| updated_by | BIGINT UNSIGNED | 0 | 最后更新人，关联 user 表 | 所有表 |
| created_at | DATETIME | CURRENT_TIMESTAMP | 创建时间 | 所有表 |
| updated_at | DATETIME | CURRENT_TIMESTAMP | 更新时间 | 所有表 |
| deleted_at | DATETIME | NULL | 逻辑删除时间，NULL=未删除 | 所有表，查询默认 `WHERE deleted_at IS NULL` |
| version | INT | 0 | 乐观锁版本号 | 仅状态机表：emergency_event、dispatch_task、consultation、care_task、transfer_task、bed、qc_issue、bed_device |

> 演示数据标记约定：patient.is_demo / news_score.is_demo / medical_record.is_demo；演示数据以环境隔离为主，生产库统一置 0，枚举中不设演示态取值。

## 二、患者数据绑定关系总览

patient 表为全域核心，各业务通过 `patient_id` 绑定；急救调度线通过 event → dispatch → ambulance 关联到患者。

| 业务域 | 表 | 与患者的绑定方式 |
|---|---|---|
| 患者接入 | patient_registration | `patient_id` 直接关联 patient |
| 证件识别 | patient_ocr_log | `patient_id` 直接关联 patient（识别结果回填登记表单） |
| 急救事件 | emergency_event | 中间表 patient_event 关联（支持一患者多事件，is_current=1 标记当前事件；登记时由任务号绑定） |
| 出警调度 | dispatch_task | `event_id` 关联 emergency_event → patient；`ambulance_id` 关联 ambulance（不直接绑患者） |
| 院前病历 | prehospital_record | `patient_id` 直接关联；多选症状/既往史/现场观察走中间表 |
| 体征与评分 | vital_sign / news_score / medical_record / follow_up / circulation_record | `patient_id` 直接关联 |
| 远程会诊 | consultation | `patient_id` 直接关联；参与医生走 consultation_member 中间表 |
| 连续诊疗 | care_task / service_record | `patient_id` 直接关联；service_record 经 `care_task_id` 级联 |
| 转诊交接 | transfer_task | `patient_id` 直接关联 |
| 预警 | alert | `patient_id` 直接关联，`care_task_id` 可选级联 |
| 床位监护 | bed | `patient_id` 关联（在院床位时非 0） |
| 车辆轨迹/设备 | ambulance_track / vehicle_device | 不直接绑患者，经 dispatch_task → event → patient 间接追溯 |
| 班组 | ambulance_crew | ambulance × user 中间表，与患者无直接关系 |

## 三、动态字典设计（状态枚举与多选项统一字典驱动）

唯一索引：`dict_item(dict_type_id, item_code)`。多选业务通过中间表关联 dict_item（见第六节）。

### 急救调度域

#### 5.6 ambulance 救护车表
| 字段名 | 类型 | 默认值 | 注释 |
|---|---|---|---|
| id | BIGINT UNSIGNED | 自增 | 主键 |
| org_id | BIGINT UNSIGNED | 0 | 关联 org 表（所属机构），普通索引 |

#### 5.7 ambulance_crew 班组表（ambulance × user 中间表）
| 字段名 | 类型 | 默认值 | 注释 |
|---|---|---|---|
| id | BIGINT UNSIGNED | 自增 | 主键 |
| ambulance_id | BIGINT UNSIGNED | 0 | 关联 ambulance 表，普通索引 |
| user_id | BIGINT UNSIGNED | 0 | 关联 user 表，普通索引 |
| crew_role | TINYINT | 0 | 班组角色: 0-未知, 1-医生, 2-护士, 3-司机 |

唯一索引：`ambulance_id + user_id + duty_date + shift_type + crew_role`（同一班次不重复排班）。

#### 5.8 ambulance_crew_history 车辆排班历史记录表
| 字段名 | 类型 | 默认值 | 注释 |
|---|---|---|---|
| id | BIGINT UNSIGNED | 自增 | 主键 |
| ambulance_id | BIGINT UNSIGNED | 0 | 关联 ambulance 表，普通索引 |
| user_id | BIGINT UNSIGNED | 0 | 关联 user 表，普通索引 |
| crew_role | TINYINT | 0 | 班组角色: 0-未知, 1-医生, 2-护士, 3-司机 |

| shift_type | TINYINT | 0 | 班次类型: 0-早班, 1-晚班, 2-顶班 |
