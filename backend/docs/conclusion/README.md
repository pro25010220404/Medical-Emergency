# docs/conclusion — 接口文档统一存放目录

依据《开发手册》3.2 后端接口文档规范设立。接口文档分为两类，均存放于本目录。

## 3.1 总结接口文档（模块级全量文档）

- 记录某个模块的**全部接口**信息，属于系统级归档文档
- **必须包含该模块所有接口**，统一字段结构：接口路径、请求方式、请求参数、请求参数类型、是否必须传入、返回参数、返回参数类型、备注
- ⚠️ **该文档不能由 AI 修改，统一手动新增或复制上去**
- 作用：模块级接口统一管理、长期归档

## 3.2 前端对接接口文档（交付文档，AI 可生成）

### 3.2.1 接口总对接文档（全量）

- 用于前端**首次对接或整体联调**某模块所有接口
- 必须包含该模块所有接口完整信息（同上字段，无备注变更说明）

### 3.2.2 接口修改文档（增量）

- 仅记录变更内容：新增字段、删除字段、修改字段类型、返回结构变化、业务逻辑调整
- 备注栏**必须说明变更内容**
- ⚠️ 生成增量文档时**必须同步修改接口总文档**（总文档手动改，AI 不得代改）
- 文件命名建议：`YYYY-MM-DD-<模块名>-接口修改文档.md`

## 命名约定

| 类型 | 命名 | 维护方式 |
|------|------|----------|
| 总结接口文档 | `<模块名>-总结接口文档.md` | 手动维护 |
| 总对接文档 | `<模块名>-接口总对接文档.md` | AI 生成 + 人工确认 |
| 修改文档 | `YYYY-MM-DD-<模块名>-接口修改文档.md` | AI 生成 + 人工确认 |

## 关联规则（开发手册 2.2 接口变更管理）

任何接口变更（增删字段、改类型、改返回结构、改业务逻辑）必须：更新接口文档 → 在变更记录注明 → 主动通知前端 → 评估影响范围，未经通知不得直接上线。
